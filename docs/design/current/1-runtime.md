## 1　系统怎样运行

本节按 [dspn_text.py](../../../dspn_text.py)（DSPNLayered、Layer）与 [hub.py](../../../hub.py) 的现状写。v0.15 纸面设计中的数值流模式、4×8 共 32 个模块的网格、NLMS 读出、远程边换边、step(x) 接口和第 1 层投影 R 均已删除，全文见 [design_v0.15](../../archive/design_v0.15/README.md)。

模块分层排列，共 L 层，每层 M 个模块（rows×cols 网格）。现行 L 档配置（[tools/queues/overnight.json](../../../tools/queues/overnight.json)）为 4 层 × 每层 2 个模块，d = 320，MLP 隐层 640，快记忆 m = 48，消息 q = 32，嵌入 64；第 2、3 层之间插中枢，带工作空间，β 上限 2。少而宽的模块来自形状扫描（E30、E32、E33）：同参数下模块越少越宽 bpc 越低、吞吐越高，召回也更好；1 个模块反而不如 2 个。代码里的 SIZES 只是起点，实际形状由 `--extra` 覆盖。

### 1.0　一个模块

同层模块参数堆叠成 [M, …] 张量，一层的计算是几次批量矩阵乘，不按模块循环。每个模块在每拍：

1. **慢通道 c。** 门 a = sigmoid(G·u + b_a)，c ← a⊙c + (1−a)⊙(B·u)，不过 tanh。b_a 初值使时间常数 1/(1−a) 在 1.5–1000 拍间对数均匀分布。0<a<1 保证循环稳定，且循环是对角线性的，可沿时间并行扫描（第 1.6 节）。
2. **快记忆 S（m×m）。** 由 c 投影出键 k（归一化）、值 v、查询 q，写入强度 β = β_max·sigmoid(w_β·c + b_β)，遗忘 γ = sigmoid(w_γ·c + b_γ)，b_γ 初值使平均保持约 64 拍。更新 S ← (1−γ)S，S ← S + β(v − S·k)kᵀ，读出 r = S·q（门控 delta 规则，同 Gated DeltaNet）。β_max = 2 允许负特征值，能主动擦除同键旧内容（E20、E26）。
3. **局部 MLP。** h = c + W₂·GELU((W₁ + A·Bᵀ)·[c, r] + b₁)，W₂ 零初始，起步时 h = c。A·Bᵀ 是秩 2 在线偏移，离线冻结（第 3 节）。
4. **消息。** z = P·h，q 维。

时间方向的记忆只在 c、S（以及中枢、工作空间）里，不经消息逐拍传播，所以整段序列可以并行训练。

### 1.0.1　层间数据流

- 第 1 层：每个模块直接读完整的字节嵌入 e(t)（没有单独的投影 R）。
- 第 ℓ 层（ℓ ≥ 2）：输入 u = [第 ℓ−1 层正下方模块本拍的 z，同层网格邻居本拍 z 之和 ÷ 4]，同一拍内自下而上算完，层间没有回环。
- 中枢之上那一层另接中枢切片（第 1.2 节）；开工作空间时每层每个模块另接 4 维广播（第 1.3 节）。

### 1.1　输入与读出

- **嵌入。** 字节查 E（256×64）得 e(t)。
- **读出接所有层。** 全部层所有模块的 h 拼起来，经 LayerNorm，再经线性瓶颈压到 64 维 y，对数几率 = E·y + b。输入输出共享 E；瓶颈零初始，使初始分布均匀，避免共享 E 时初始对数几率过大。
- 读所有层而不只最上层：底层保留的字节细节可以直达读出，上层不必把它们一路搬上来。共享 E 的代价是 softmax 秩瓶颈（随上下文变化的对数几率只能落在 E 张成的 64 维子空间里），这是嵌入维数不取太小的原因。

### 1.2　全局记忆中枢

中枢（hub.py）插在第 hub_after 层与下一层之间，不属于网格，是唯一跨模块按内容取回的通道。依据：单个模块没有跨模块召回手段，线性循环在原样召回上弱于注意力（Zoology），中枢与召回的实验见 E18、E21–E23、E28。

- **读入。** 第 hub_after 层全部模块本拍的消息，加本拍字节嵌入 e(t)（旁路：消息是压缩过的，原样复制所需的字节身份可能已丢）。
- **门控 delta 头。** L 档 4 头，每头 d_k = 64。k、q 归一化，β = β_max·sigmoid(·)，保持率 α = sigmoid(·)；S ← αS，S ← S + β(v − S·k)kᵀ，o = S·q。各头 b_α 初值按异质时间常数 τ = 300 / 3,000 / 30,000 / 10⁶ 拍设置（α = 1 − 1/τ）。
- **持久头。** τ ≥ 10⁵ 的头在会话边界不清空（第 1.4 节），跨会话保存信息；其余为短时头。持久头要学会跨越 T 字节以外的保持，训练时需要跨批次延续状态（`--stateful`，第 3 节）。
- **输出。** 各头读出拼起来经 W_o 投影，切给上一层每个模块 32 维，作为额外输入。
- **在线偏移。** 读路径 W_q、W_o 各带秩 2 偏移，离线冻结，在线更新，睡眠时精确并入（第 3 节）。写路径经 S 跨时间循环，只离线训练。
- v0.15 的可选滑动窗口注意力头已删除（未使用）。

### 1.3　全局工作空间（基础版）

依据与机制讨论见 [8.7](../basis/8-brain-hierarchy.md)。实现（`ws_*`）：

- 4 个槽位 × 16 维。按 64 拍分块，块边界按全局位置对齐，逐拍与整段计算结果一致。
- **写入。** 每块末，所有层所有模块末拍的消息先做 RMS 归一化，加模块身份向量，每个槽位对全部模块做 softmax 软竞争得写入内容，再与旧槽位按每槽可学的保留门混合。
- **广播。** 下一块里，槽位经每层一个零初始矩阵投影，给每层每个模块 4 维额外输入；零初始使起步等于无工作空间。块内仍整段并行，块延迟避免跨模块的逐拍非线性循环。
- **为什么归一化。** 槽位 → 下一块输入 → 消息 → 槽位是跨块的非线性环路，增益过 1 时会逐块指数爆炸（E43）。
- 效果：bpc 与召回都持平无工作空间（E34）；T = 1024 时分块反而更快（E37），按用户决定保留。完整版（硬竞争、选择性读、稀疏更新、点燃、预测编码）使训练锁死或发散（E35），已删除。

### 1.4　会话边界字节

字节 SEP = 30（ASCII 记录分隔符）标记会话边界。读到它时：各层 c 的门置 0（扫描把 a 钳在 0.01，只留 1% 旧状态），快记忆 S 的 log α 置 −30（清空），中枢短时头清空，持久头不动。输入比例 (1−a) 用原门值计算：边界处只清旧状态，不放大写入（E42：先置 0 再算输入使写入放大约千倍，训练 NaN）。聊天的 /new 就是输入这个字节，与训练一致。

### 1.5　可插拔机制（默认关）

都由构造参数打开，权重为 0 或不设即关；有测试，但都未进入现行配置。

- **预测学习**（`pred_self`、`pred_nb`、`pred_down`）：每层一个线性预测头，用本拍 h 预测下一拍的消息——自己的、网格邻居的、正下方下层模块的（自上而下）。目标停梯度，误差按目标方差归一化（防止消息坍缩成常数），加权进辅助损失。
- **局部学习**（`local=True`，SOLO 式）：层间消息（含进中枢、工作空间的）停梯度，每层只由读出路径和自己的预测损失训练；模块内部（扫描、快记忆、MLP）仍反传。
- **惊讶门控写入**（`surprise`，需 `pred_self`）：第 i 层上一拍自我预测与本拍消息的相对误差 s 作惊讶度，第 i+1 层（与中枢）的写入强度 logit 加 a·(s − 1)，a 可学、初值 0（等于不门控）。上一拍的预测存在状态里，逐拍与整段一致。
- **词级层**（`word_*`，SpaceByte 式，设计 9.5）：只在词边界字节处运行的一摞层，中枢移到词级。S 档同参数下明显更差（E38）。
- **字节自上而下层**（`td_layers`，取自 TSPH 两扫）：上层上一拍输出预测下层本拍消息，[预测, 误差] 输入额外的字节层，输出进读出。本身有小益处，但同参数下不如把参数给主干（E38、E40）。

### 1.6　计算怎样跑满 GPU

- **同层堆叠。** 每层是几次 einsum；读同一输入的投影合并成一次（G 与 B 一次；K、V、Q、β、γ 一次）（E39）。
- **慢通道扫描**（`scan`）：两级并行。块长 8，块内用 log a 的累加和一次算完；块尾用 Hillis–Steele 前缀衔接，串行步数为 log₂(块数)。块长不能加大：块内的 exp(−Σlog a) 在块长 16 时会逼近 fp32 上限，反传溢出（E41）。
- **快记忆与中枢**（`delta_chunk`）：分块 WY 形式的门控 delta 规则，块长 64，块内三角求解一次算完，块间顺序传状态（Gated DeltaNet 分块算法，结构参照 flash-linear-attention 的参考实现）。逐拍（T=1）时不补齐，与整段结果一致。
- **CUDA Graph。** 整个训练步（前向、反传、裁剪、AdamW）录成一张图，之后每步只回放；瓶颈是小运算的调度次数而不是计算量（E39）。
- **单流部署**（采样、聊天）逐拍调用同一个 forward，状态由调用方带着走。
