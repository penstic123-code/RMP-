# 11　潮汐网络（Tide）：净室新起点提案

状态：提案，未实现、未跑过任何实验。本文所有吞吐、显存、参数量都是估算，以 V1 实测为准。
写作时没有读旧设计文档和代码，只读了文献主题文件和实验记录；实验里的旧部件只当证据用。

## 1　一段话总述

潮汐网络是一摞相同的积木块，外加一张表。每块里有一块“快记忆”（一个固定大小的矩阵，读到什么就按纠错规则记一笔，不占参数，读多长的文本都一样大）和一个普通的小型前馈网络；整摞中间插一张“槽表”（几千行的键值表，每个词元只查其中十几行）。**预训练用普通的反向传播，整条序列并行算；部署时只改槽表里“今天被异常频繁查到”的少数几行；睡眠时把白天的文本和旧语料混着重放，过了考试才保留。** 白天涨潮（写快记忆和少数槽），夜里退潮（沉到全部慢权重里），所以叫潮汐。

三种记忆、三种速度，全文只有这三样东西在“记”：

| 名字 | 是什么 | 多久改一次 | 谁来改 |
|---|---|---|---|
| 快记忆 S | 状态（不是参数），每层 2 个矩阵 | 每个词元 | 纠错规则，前向时自动发生 |
| 槽表的值 V | 参数，4096 行 | 部署时每 256 个词元 | 梯度下降，只改选中的几十行 |
| 其余慢权重 | 参数 | 只在预训练和睡眠 | 梯度下降，全部 |

## 2　结构

### 2.1　数据流

```
文本 → 分词（BPE，4096 个词元）→ 嵌入 E（查表得到 d 维向量 x）
  → 块 1 → 块 2 → 槽表 → 块 3 → 块 4 → 归一化 → 乘 Eᵀ → 下一个词元的概率
每个块：  x ← x + 快记忆(norm(x))        # 读写本层的 S
          x ← x + 前馈(norm(x))          # 两层全连接，中间宽 4d
槽表：    x ← x + g · 查表(norm(x))
```

没有注意力层，没有模块、中枢、工作空间、词级层、自上而下层。norm 是 RMSNorm（把向量长度调到 1 附近，防止数值越滚越大）。

### 2.2　快记忆（每块一个）

解决的问题：在固定大小的状态里记住“前文出现过的 A 对应 B”，以后看到 A 能取回 B。

每层有 H=2 个头，每个头有一个矩阵 S（dv × dk）。每来一个词元，由 x 线性算出：键 k、查询 q（都除以自身长度，长度为 1）、值 v、写入强度 β∈(0,2)、保留率 α∈(0,1)。

```
写：  S ← α · S · (I − β k kᵀ) + β v kᵀ
读：  o = S q        →  输出 = Wo · norm(o)
```

把写入式拆开看就是 `S ← α·S + β (v − α·S k) kᵀ`：先看记忆里 k 现在对应什么（S k），和想存的 v 差多少，只把差额补上。这就是“纠错规则”（delta 规则）。它只用到这个矩阵自己的输入 k、目标 v 和当前内容，是局部规则。

- 头 A：α 由输入决定（会淡忘，管近处）。
- 头 B：α 固定为 1（永不淡忘，只会被同一个键的新内容覆盖，管远处和跨会话）。

为什么不能更简单：
- 去掉纠错项（只做 `S ← αS + v kᵀ`）就是普通线性注意力，键一重复或相近就互相串扰；实验里纠错式快记忆的召回明显更好（E28、E32）。
- 只留一个头：要么淡忘（找不回远处），要么不淡忘（近处细节挤占容量）。两个头是“近”和“远”的最小划分。
- k、q 归一化是必须的：长度为 1 且 β<2 时，写入不会把 S 放大，状态有界。

尺寸：d=256，dk=dv=128，每层状态 2×128×128 = 32,768 个数，4 层共约 13 万个数（约 0.5 MB），**与读了多少文本无关**。容量上限粗略是每个头约 dk 个互不相似的键，全网约一千条关联；超出后旧的被新的逐渐覆盖。

### 2.3　沿序列并行训练（一等目标）

上面的写法是一拍一拍的，直接这样跑会很慢（E39：瓶颈是小运算的次数，不是计算量）。训练时用数学上等价的**分块并行**形式（Gated DeltaNet 的做法）：

- 把 1024 个词元切成 16 块，每块 C=64。
- 块内：64 拍之间谁影响谁，写成一个 64×64 的下三角方程组，用一次批量三角求解加几次矩阵乘法算完，块内没有循环。
- 块间：只把块尾的 S 传给下一块，每层串行 16 步（不是 1024 步），每步都是大矩阵乘法。
- 头 B 就是 α=1 的特例，同一段代码。

实现：自己用纯 PyTorch 写这个内核（`torch.linalg.solve_triangular` + `matmul`，约 50 行），另留一个逐拍循环的版本只做单元测试对拍。现成的 flash-linear-attention 库有同一算法的内核（`chunk_gdn`），但它的内核基于 Triton，官方安装说明没有提 Windows，所以不依赖它，只在对拍时可选用作第三方参照。前馈、槽表、嵌入、读出天然逐位置并行。

吞吐估算（待 V1 实测）：
- 依据一：同一块 GPU 上，运算次数少的模型（GRU、Transformer）在 S 档达到每秒近百万字节（E15、E16）；旧架构把串行步数从 64 压到 6 后，S 档到每秒 18–25 万字节（E32、E38）。本设计全网串行步数是 4 层 × 16 块 = 64 次大矩阵运算。
- 依据二：Gated DeltaNet 原文报告其训练吞吐与 DeltaNet 基本相同、略低于 Mamba2，2K 上下文内 Transformer 最快。所以预期是同参数 Transformer 的 1/3–1/2，而不是 1/37（E14）。
- 估计：全尺寸约每秒 3–6 万词元，折合每秒 11–22 万字节，是现有参考（约 470 万参数时每秒 4 万字节）的 3–5 倍。
- 门槛（V1）：全尺寸 ≥ 每秒 2.5 万词元（约 9 万字节，参考的 2 倍以上），且不低于同参数 Transformer 的 1/3。

### 2.4　前馈

`前馈(x) = W2 · gelu(W1 x)`，W1：d→4d，W2：4d→d。最普通的两层全连接。它存放语言规律，部署时冻结。不换成稀疏结构的理由：Memory Layers 原文的消融显示，把太多前馈层换成稀疏表会变差。

### 2.5　槽表（全网一张，插在第 2、3 块之间）

解决的问题：部署后要往参数里写新东西，又不能动到存旧规律的权重。办法是给“新东西”一个单独的、稀疏访问的地方：每次只碰几行，没被碰到的行里的旧内容物理上不会变。

```
u = P · norm(x)                      # 降到 64 维，再除以长度
分数 = τ · K u                       # K：4096 行键，每行长度为 1
I = 分数最高的 16 行                  # 其余 4080 行不参与
w = softmax(分数[I])
查表(x) = Σ_{i∈I} w_i · V[i]         # V：4096 行值，每行 d 维
g = sigmoid(a·x + b)                 # 一个数：现在该不该听槽表的
```

为什么不能更简单：
- 不要槽表、直接在线微调前馈：全量微调会冲掉旧知识（E25、E29；Sparse Memory Finetuning 原文的对照也是这样）。
- 用低秩偏移代替：试过，不遗忘但学得少，学习率一调高就开始遗忘（E29、E31）。槽表保留作为 V2 的对照组，谁赢用谁。
- 只放一张、放中间：照 Memory Layers 与 Sparse Memory Finetuning 原文的放法；放中间还有一个好处，在线学习时梯度只需回传上面两块。

### 2.6　分词：小词表 BPE，而不是字节

选 4096 个词元的 BPE（在 TinyStories 加对话数据上训练；会话分隔符、`User:`、`Bot:` 各占一个词元）。理由：

1. 速度：同样的每秒步数，一个词元约抵 3.5–4 个字节（待 V0 实测），8 小时能读完的文本多 3–4 倍，1024 长的序列覆盖约 4 KB 文本。
2. 记忆：快记忆按“键→值”存。词元级的合成召回能学会（E28、E32），字节级的自然文本人名召回一直学不会（E18、E23、E36）。一个猜测是名字拆成字节后没有一个干净的键；换成词元是最便宜的检验办法。
3. 层级的证据：小规模下想让模型自己学分块都不如不分（E38、E40，hierarchy-topdown.md 的 H-Net 小规模复现）。固定的 BPE 不需要学。

代价：嵌入表占约 105 万参数（输入输出共用一张）。这是猜测性最强的决定之一，所以 V1 里直接放一个字节版对照组，用“每字节比特数”（总损失 ÷ 总字节数）统一比较。

### 2.7　尺寸与预算

| 部件 | 算式 | 参数 |
|---|---|---|
| 嵌入（输入输出共用） | 4096 × 256 | 105 万 |
| 快记忆 × 4 | 每块 q、k、v、输出四个 256×256 投影 + 门 ≈ 26 万 | 105 万 |
| 前馈 × 4 | 每块 2 × 256 × 1024 ≈ 52 万 | 210 万 |
| 槽表 | 键 4096×64 + 值 4096×256 + 投影 | 133 万 |
| 合计 | | 约 550 万 |

- 显存（估算）：批 16 × 1024 词元。每层为反向传播保存的中间量约 0.3 GB，4 层约 1.2 GB；输出概率 16×1024×4096 个数及其梯度约 0.8 GB；合计约 2.2 GB，开混合精度后更低。超了就退到批 8。V1 的冒烟测试实测，门槛是峰值 ≤ 2.8 GB（E39 的教训：超出后溢出到内存，极慢）。
- 时间：按门槛下限每秒 2.5 万词元，8 小时约 7 亿词元，约等于 TinyStories 一遍。
- 优化器：AdamW，学习率 1e-3 起，余弦下降；门的偏置不做权重衰减（E35 发现的问题）；全尺寸不用 2e-3（E38 的发散判断）。
- 公平对照：Transformer 和 GRU 用同一个分词器、同样的总参数（差 2% 以内）、同样的数据顺序；各自在 3 个学习率里取最好的（E16 的教训）；同时报“同词元数”和“同墙钟时间”两种比较。

## 3　学习

### 3.1　预训练（改全部参数）

- 目标只有一个：预测下一个词元的交叉熵。
- 数据按流读：每一行批数据是一条连续的文本流，这一段的 S 传给下一段，梯度不传。这样模型见过“状态里已经有很久以前的东西”的情形，记忆对话跨会话的问题才有训练信号（Delayed Supervision 一文的结论方向相同）。
- 数据混合：TinyStories 为主，后段混入 SODA 对话和模板化记忆对话，会话之间不清空 S。
- 训练图里没有任何在线规则：槽的选择统计、睡眠、验收都不进训练。预训练结束时顺手统计一次每个槽在训练数据上的访问频率，存成一个 4096 长的向量（下面要用）。

### 3.2　部署时在线学习（只改槽表的少数几行值）

每读完 256 个词元做一次：

1. 数这 256 个词元里每个槽被查了几次，得 c(i)。
2. 打分：`分(i) = c(i)/Σc × log((|B|+1) / (背景批次中用到槽 i 的批次数 + 1))`。意思是“这段话里用得多、平时很少用”的槽得分高。（Sparse Memory Finetuning 原文公式。）
3. 取分最高的 t 行（先试 t=32）。
4. 对这段话的下一词元损失做一次反向传播，只更新这 t 行的 V，用不带动量的普通梯度下降。键 K、嵌入、读出、前馈、快记忆的投影全部不动。

快记忆 S 照常每个词元都在写，会话结束不清空，关机时存盘（0.5 MB）。

为什么这样不容易遗忘：旧规律在前馈、嵌入、读出里，一个数都没改（E29 查明遗忘主要来自共享读出层）；槽表里平时常用的行因为打分里的 log 项被排除。为什么还能学会：被选中的行正是当前内容最常触发的行，改它们的值直接改变这类上下文下的输出。

### 3.3　睡眠巩固（改全部慢权重，可回滚）

白天把读过的文本存进一个固定大小的池，池满时优先留下损失高的段落（SuRe 的做法）。睡眠：

1. 存一份“早晨模型”快照。
2. 重放：池里的新文本与旧语料按 1:3 混合，小学习率训练几百步，改全部慢权重。
3. 约束：只在**旧语料**的批次上加一项“输出分布别偏离早晨模型”（KL）。新文本上不加（E36：对新内容用早晨模型当老师等于教它忘掉新词）。
4. 考试：旧语料留出集不变差、新内容留出探针不变差，才保留；否则回滚到睡前。探针和报告用的测试句分开（E36 的教训）。
5. 保留每次通过的快照，不只留最后一个（Darwin Gödel Machine 的做法）。

睡眠的作用是修补白天残余的遗忘，并让键、前馈也适应新内容。如果 V3 显示睡不睡没有差别，就删掉这一节。

## 4　四个目标各靠什么

| 目标 | 靠什么 | 为什么 |
|---|---|---|
| 边用边学不遗忘 | 槽表稀疏写入（3.2）+ 睡眠（3.3） | 白天只改几十行很少用的值，旧规律所在的权重没动；夜里用旧语料重放和早晨模型约束修补 |
| 固定内存读长文 | 快记忆（2.2），头 B 不淡忘 | 状态就是 8 个固定矩阵；按键取值，不按距离取 |
| 学会语言、能聊天 | 整摞块用反向传播训练；BPE；流式训练 | 语言能力来自最普通的“堆叠 + 下一词元预测”，不靠任何新奇部件；跨会话记忆靠不清空的 S，长期知识靠槽表 |
| 接近大脑 | 三种速度的记忆、纠错式局部写入、稀疏访问、睡眠重放 | 见第 5 节；凡是会损害可用性的仿生做法（纯局部学习规则）都没有采用 |

## 5　和大脑的对应（类比，不是声称等同）

- 快记忆 ≈ 海马式的快速绑定：一次就记住，容量小，会被覆盖。写入规则只用本地量。
- 槽表 ≈ 皮层里稀疏的记忆痕迹：每次只有约 0.4% 的行活动；“新奇才写”类似新奇性调制可塑性。
- 前馈与嵌入 ≈ 慢学习的皮层：只在离线时改。
- 睡眠重放 ≈ 互补学习系统理论里的系统巩固：新旧交替重放。
- 不像大脑的地方：预训练和睡眠用反向传播；在线写槽表的误差信号也是反向传播来的（只是改动范围局部）；没有脉冲、没有树突。learning-rules.md 的结论是纯局部规则目前比反向传播差一倍以上，所以不为像而用。

## 7　验证计划

按顺序做，前一个不过就先修或按“不过怎么办”处理，不往后堆。指标统一用验证集每字节比特数（bpb）。

**V0　对拍与分词（约 15 分钟，不训练）**
- 分块并行内核与逐拍循环在随机输入上输出一致（最大差 < 1e-4）；读 1 千与 10 万词元后状态字节数相同；实测每词元平均字节数。
- 门槛：全部通过。

**V1　小档能不能学语言、够不够快（约 90 分钟）**
- 小档约 130 万参数（d=128，3 块，槽表 1024 行）。五组各训练 15 分钟墙钟时间，TinyStories，同种子：① Tide；② Tide 去掉槽表（参数补到前馈）；③ Tide 字节版（词表 256，参数补到块里）；④ 同参数 Transformer；⑤ 同参数 GRU。
- 吞吐对比：每组记录每秒词元数和每秒字节数；另对全尺寸 550 万的 Tide 与同参数 Transformer 各跑 150 步冒烟，记录吞吐和峰值显存。
- 合成召回：Tide、Transformer、GRU 各跑一次 E28 同设置的键值召回（共约 10 分钟）。
- 门槛：(a) 全尺寸吞吐 ≥ 每秒 2.5 万词元，且 ≥ 同参数 Transformer 的 1/3；峰值显存 ≤ 2.8 GB。(b) 同墙钟下 ① 的 bpb ≤ ④⑤ 中较好者 + 0.03。(c) ① 不比 ② 差 0.02 以上（槽表不拖后腿）。(d) 召回准确率 ≥ 0.9。
- 不过怎么办：(a) 不过先调块长和批大小，仍不过则本提案不成立；③ 比 ① 好 0.03 以上就改用字节；(c) 不过就把槽表缩小或改成加在最后一块之后。

**V2　在线学习不遗忘（约 1 小时，用 V1 的检查点）**
- 沿用 E25、E31 的生造词教学流程（先读一段旧故事，再读教学文本）。对照：① 槽表稀疏写入；② 同一模型全量微调；③ 同一模型低秩偏移（E31 的做法）；④ 槽表随机选同样多的行（检验打分公式是否有用）；⑤ GRU 低秩。
- 指标：新词留出句的 bpb 下降量；旧数据 bpb 上升量；清空 S 后新词是否还在。
- 门槛：① 的新词下降量 ≥ ② 的 60%，同时旧数据上升 ≤ 0.03；并且在“学多少 / 忘多少”上不差于 ③。
- 不过怎么办：扫 t 与学习率；仍不如 ③ 就用低秩偏移替换 3.2，槽表只保留作容量。

**V3　睡眠有没有用（约 1 小时）**
- 接 V2，连续 3 个“白天学一个新词 + 夜里睡一次”的循环。对照：不睡；只重放不加约束；完整睡眠。
- 门槛：完整睡眠 3 次全部通过考试；3 天后旧数据 bpb 与出厂时相差 ≤ 0.02，3 个新词的探针都不比各自睡前差 0.03 以上；且优于不睡。只看当次考试是短视的，所以要看连续 3 次（cognition-selfimprove.md，Huxley-Gödel Machine）。
- 不过怎么办：若不睡同样好，删掉睡眠。

**V4　固定状态找回远处细节（约 2 小时）**
- (a) 自然文本人名召回，E18 的流程：真名字与换名对照的命中率差。(b) 模板记忆对话：事实与提问之间隔 1 千 / 4 千 / 1.6 万词元的无关文本。对照：中途清空 S（应掉到瞎猜水平）；GRU；上下文 1024 的 Transformer。
- 门槛：(a) 差值 ≥ 0.05（此前所有模型都约为 0）。(b) 隔 1.6 万词元时答对率 ≥ 50%，高于 GRU，且清空对照接近瞎猜。
- 不过怎么办：先加大 dk；仍不过则承认需要一层有限窗口的注意力（见第 8 节）。

**V5　通宵预训练（每个模型一夜，共三夜）**
- 全尺寸 Tide、Transformer、GRU，同数据同词元数。
- 门槛：Tide 的 bpb ≤ Transformer + 0.03；跨会话记忆对话答对率 ≥ 60%，清空 S 的对照 ≤ 瞎猜 + 5 个百分点；生成的对话不替用户续写。

**V6　整套流程演示**：通宵模型上重复 V2–V3 一周量级的循环，看可塑性是否下降、槽表是否写满。只在 V1–V5 通过后做。

## 8　风险和不确定处

1. **远距离细节找不回（最可能失败）。** 快记忆容量只有约一千条关联，且文献里长程检索主要靠注意力；项目里自然文本的人名召回从未成功过（E18、E23、E36）。换成词元和流式训练是否足够，没有证据，只有 V4 能回答。
2. **槽表在线学得不够。** 只改几十行的值、键不动，可能学不会需要新“地址”的内容。原文是 13 亿参数模型加 100 万行的表，缩小两百多倍后是否成立未知；原文用的学习率很大，小模型上要重扫。
3. **槽表训练中出现大量死行。** 取前 16 行意味着没被选中的行没有梯度。原文提到小模型配大表时不稳定、需要归一化。本设计已归一化，但没有别的保险。
4. **吞吐估算偏乐观。** 三角求解在混合精度下要转回单精度；Windows 上用不了 Triton 内核和可能用不了编译加速。这是为什么吞吐放在 V1 的第一条门槛。
5. **小模型接近饱和。** 文献指出没有余量时重放也救不了遗忘；550 万参数读完一遍 TinyStories 后还剩多少余量未知。槽表是专门留的余量，但没有验证。
6. **BPE 的代价。** 嵌入占掉约五分之一参数；生造词会被拆成几个词元。V1 有字节版对照。
7. **训练久了快记忆被慢权重“吞掉”。** continual-sleep.md 里 Strategy Coopetition 一条（未核实）提示上下文内学习可能先出现后消失，V5 期间要定期跑 V4(b)。
8. **状态永不清空的副作用。** 头 B 不淡忘，长期使用后可能被无关内容填满而变成噪声；V6 才会暴露。
9. **依据的强度有限。** 多数 2026 年文献只核对了摘要或完全没核实（第 6 节已逐条标注）；项目自己的实验几乎都是 S 档、单种子。
