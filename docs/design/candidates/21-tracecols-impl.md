## 21（续）　TraceCols v2 的实现：迹的算法、显存、提速、验证

设计见 [21-tracecols.md](21-tracecols.md)。施工顺序只在 [plan/research-lines.md](../../plan/research-lines.md) 的 TraceCols 节。

### 21.10　衰减迹的算法

每头衰减 γ_t = σ(a·u_t + b_h)。记 c_t = ∂logγ_t/∂b_h = 1 − γ_t，P_{s→T} = Π_{r=s+1..T} γ_r，S₀、E₀ 是块起点的状态与迹（E = ∂S/∂b_h，与 S 同形）。逐拍：E_t = γ_t·(E_{t−1} + c_t·S_{t−1})。

- **块末闭式**：E_T = P_{0→T}·(E₀ + (Σ_t c_t)·S₀) + Σ_s P_{s→T}·C_{>s}·v_s k_sᵀ，C_{>s} = Σ_{t=s+1..T} c_t（审查已独立推导核对）。
- 最后一项 = 同一递推从零起步、把 v_s 换成 C_{>s}·v_s 后的末状态：**多调一次只求末状态的融合内核**。C_{>s} 用到块内后面的 c，但只在块末算迹时用，不影响前向因果。
- **累进梯度**：块内起点状态写成 S₀ + E₀·(b_h − b_h.detach())（值不变），自动求导给出的 ∂L/∂S₀ 正好乘上 E₀ 加进 b_h 的梯度，不重复计数。起点状态对读出的贡献 o_t += P_{0→t}·S₀ q_t 在内核外用闭式算，不依赖内核是否回传初值梯度。
- 推进迹用旧参数（在线 e-prop 的通常近似）。多层、多级时，整段梯度还包含经后层起点状态与上级输入的路径，分块版有意丢掉，所以正确性门槛只定义在单层、参数固定的情形（21.8）。

### 21.11　显存

- 迹与状态同形：每条流的迹显存 = 状态显存。
- 小规模默认配置（第 0 级 d₀=128、4 头 32×32、编码 2 块 + 解码 1 块；第 1 级 d₁=256、8 头 32×32、4 块）：状态约 5 万个数，迹同样约 5 万，每条流约 0.4 MB（fp32），批 64 约 25 MB。
- 显存主体是激活值，用每块激活检查点控制；迹不限制批大小。

### 21.12　提速（按收益排序）

| 手段 | 做法 | 收益来源 |
|---|---|---|
| 层级压缩 | 宽的第 1 级只跑约 1/5 的位置 | 主干算力按序列长度降 |
| 一专家路由 | 按专家分组的批量矩阵乘；容量系数 1.25，超出的位置只走残差 | C 倍参数、约 1 倍算力，形状固定 |
| 融合内核 | 时间混合用 fla 分块内核；衰减迹多一次只求末状态的调用 | 无 O(T²) 中间张量；迹约增加 10% 时间混合开销 |
| 静态形状 | 每行每块片段数上限 = 块长 / 3，最大片段长度 16 字节（强制边界）；都只看过去，在线同样执行 | 第 1 级序列补齐到固定长度，可编译 |
| 长块 + 激活检查点 | 块 2048 字节；批 × 块长填满 GPU | 块与块之间无冷启动 |
| bf16 | 矩阵乘与内核 bf16；状态、迹、衰减累乘 fp32 | 约 1.5–2 倍 |
| 编译 | torch.compile + CUDA graphs | 去掉小运算与 Python 开销 |

### 21.13　测试阶梯（每级过了才进下一级）

| 级 | 测什么 | 花费 |
|---|---|---|
| 1 正确性 | 单层衰减迹：分块 = 整段；因果：改未来字节、改片段长度都不影响过去输出（含展开只用片段起点）；稳态边界率收敛到目标 | 秒 |
| 2 合成任务 | 长延迟：键值对在短延迟上学会存取，再测 1 万字节延迟——看衰减能否被迹拉长（写什么靠块内学会，不声称跨块学会写）；复制 / 多键值召回；A→B→A 顺序任务遗忘 | 每项几分钟 |
| 3 语言小规模 | TinyStories：冷启动与预热流式 bpc、吞吐、21.7 五项指标 | 每组十几分钟 |
| 4 一生协议 | 在线读新语料（莎士比亚）+ 睡眠：旧语料 bpc 变化、新语料 bpc 下降 | 几分钟 |
| 5 规模曲线 | 3 个规模同“字节 / 参数”比，bpc − 参数量斜率；变平说明截断或局部学习有天花板 | 约一天 |
| 6 对话 | 海马 + 对话微调 + 记忆脚本，对照 21.8 | 半天 |

### 21.14　放大到 10 亿参数（推测，未测）

- 迹不再是瓶颈（与状态同形）；不用级联时，每参数只有权重与优化器状态。
- 10 亿总参数、8 专家时，每拍激活参数约 2.5 亿；主干只在约 1/5 的字节上算，每字节训练约 4×10⁸ 次浮点。数据按每参数约 80 字节计约 800 亿字节，共约 3×10¹⁹ 次。
- 8×H100（有效约 2.4×10¹⁵/秒）：约半天到一天（路由与压缩的实际利用率低于稠密模型）。
- 本机 RTX 5060 Laptop：算力约 40 天，且参数 + 优化器状态超出 8 GB——本机实际上限约 1–3 亿总参数（8 位优化器 + 激活检查点）。
- 稀疏专家的 10 亿总参数，能力大致相当于更小的稠密模型；截断与局部学习的代价由第 5 级规模曲线回答。
