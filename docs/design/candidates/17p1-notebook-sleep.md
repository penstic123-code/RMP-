## 17-P1　笔记本 + 夜间入脑（现成 1.7B 模型，外置记忆，睡眠时改参数）

### 一段话总述

直接用开源的 Qwen3-1.7B 当“大脑”（智力和说话能力现成），不再自己预训练。记忆分两处：用户说的事实先写进一个**外置笔记本**（本地数据库，下一句话就能用，跨会话不丢）；每晚“睡眠”时，把当天的对话和笔记训练进一个**低秩适配器（LoRA）**，让知识、能力、说话风格真正进到参数里，并用验收探针决定接受还是回滚。聊天时不改参数，参数每晚改一次。这是三套里借得最多、自研最少、成功概率最高的一套。

### 结构与规模

| 部件 | 内容 | 规模 |
|---|---|---|
| 基座 | Qwen3-1.7B（Apache-2.0，28 层，上下文 32K，可关思考模式），权重冻结 | 4-bit 量化约 1.5 GB 显存；bf16 约 3.4 GB |
| 适配器 | LoRA 秩 16，挂在全部注意力与 MLP 投影上；一快一慢两份 | 约 1,700 万可训参数（估算），磁盘约 70 MB/份 |
| 笔记本 | SQLite：事实卡（主语-属性-值-时间-来源句）、对话原文片段、用户画像（一段约 300 词元的文字） | 文本，MB 级 |
| 检索器 | 小型句向量模型（如 bge-small，CPU 上跑）+ 关键词；取前 5 条放进系统提示 | 约 3,000 万参数，不训练 |
| 档案 | 每次被接受的适配器存一份，带探针成绩 | 每晚约 70 MB |

显存：聊天时 4-bit 基座 + 适配器约 2.5 GB；睡眠训练（QLoRA，序列 512、批 4、梯度检查点）估算 5–6 GB，在 7 GB 之内。若渲染程序同时占显存（E39 遇到过），退到 Qwen3-0.6B（训练约 3 GB），智力下降一档。

时间：**没有预训练**，第一天就能聊。生成约 20–40 词元/秒（估算）。每晚睡眠 300–600 步、约 10–30 分钟（估算，第一个实验实测）。

### 学习方式

**离线（一次性）**：无。只需下载基座，写笔记本与睡眠脚本。

**使用时（不改参数）**：
- 每轮回复前：用当前这句话去笔记本检索，把命中的事实卡和用户画像放进提示。
- 每轮回复后：让模型自己做一次“抽取”——这句话里有没有值得记的事实？有则新增；与旧卡冲突则改写旧卡并保留旧值与时间（Mem0 的“新增 / 更新 / 删除”三操作）。抽取不可靠时退回规则：凡含 “my / I am / remember that” 的句子原文入库。
- 用户纠正（“不对，应该是…”）或点踩：记成高优先级样本。

**睡眠时（改参数）**，每晚或用户点“睡觉”时跑一次，共五步：
1. **造题**：对当天每条新事实，让模型自己写 5–8 个不同问法的问答和推论（SEAL 的“自我编辑”，只用它的造数据部分，不跑外层强化学习）。当天对话原文也入训练集，只对助手回复且未被用户否定的部分算损失。
2. **回放**：混入三类旧内容——历史事实题（按“上次答错的优先”抽）、基座自己生成的通用对话（自生成回放）、少量 SmolTalk 原文。新旧比约 1:1。
3. **训练**：只训 LoRA。损失 = 新内容的交叉熵 + λ·KL(冻结基座 ‖ 当前模型)，KL 只在回放样本上算，作用是“别的事情上保持和原来一样”。同时维护一份慢适配器（快适配器的滑动平均），推理只用慢的。
4. **验收**：三组探针。新知识：**不给笔记本**直接问，答对率要升；旧知识：固定的 200 道通用题与历史事实题，下降不超过 2 个百分点；反事实对照：把名字换成没教过的，模型不应同样自信。三组都过才接受。
5. **存档或回滚**：接受则存进档案并成为明天的模型；不过则丢弃当晚的适配器，笔记本不受影响（所以回滚不会“失忆”）。

**防遗忘靠四层**：基座永不改；只训低秩；KL 回放；验收不过就回滚。本项目已验证过其中三层的方向：只改低秩偏移几乎不伤旧知识（E29），带回放和锚的睡眠能提交（E31），无回放的睡眠会毁掉旧知识（E25）。

**为什么使用时不改参数**（需求 6 的说明）：一句话的梯度噪声大，边聊边改容易把模型带偏，本项目的在线更新就出现过明显遗忘（E25、E29）；而事实通过笔记本已经“下一句就生效”，不需要靠立即改参数来记住。参数的改变集中到每晚，一次用一整天的样本，有回放、有验收、可回滚。对用户来说：模型仍然是“用着用着参数就变了、越来越懂你”，只是变的时刻在夜里而不是每句话之后。空闲超过 10 分钟也可触发一次小睡（同流程、步数减到 100）。

### 三种自我改进与记忆：怎么实现、怎么测

| 需求 | 实现 | 测法 |
|---|---|---|
| 会话内记忆 | 上下文窗口（32K，足够几十轮） | 同会话隔 20 轮问早先事实，答对率 |
| 跨会话记忆 | 笔记本检索；睡眠后进参数 | 教 50 条事实，新开会话问：隔 1 / 7 / 30 天；含“改口”题（旧值已被更新） |
| 知识 | 事实卡 → 自造问答 → LoRA | **闭卷**答对率（关掉笔记本），睡前对睡后；反事实换名对照 |
| 能力 | 常聊领域的对话原文 + 用户纠正进训练；可加该领域的公开语料 | 选用户常做的一种任务，留出 30 题，每周测一次，对比冻结基座 |
| 适应用户 | 用户画像（即时）+ 对话原文进 LoRA（长期） | 关掉画像后，偏好遵守率（例如“回答要短”“不要列表”）；用户盲选新旧模型的回复 |

### 为什么最可能成功

主观成功概率 **约 75%**（指六条需求全部达到可演示水平）。理由：
- 需求 2、3 靠现成模型直接满足，不占训练预算。本项目从零训练的小模型在几百万参数下连故事里的名字都复述不出（E18、E23），一个通宵能训的 5,000 万参数与基座相比，差距不是架构能补的。
- 需求 5 靠笔记本，是确定性的工程，不依赖模型学会什么。
- 需求 4、6 靠夜间 LoRA，流程里每一步都有公开结果或本项目自己的实验支持，且失败时有回滚。
- 最大的不确定只剩一处：1.7B 模型经一晚 LoRA 后，闭卷记住事实的比例有多高。即使这一处只做到一半，笔记本仍然兜底，整套系统照样可用。

扣掉的 25%：闭卷入脑率可能很低（见最后一节）；量化 + Windows 的工具链问题；长期（几十晚）累积漂移没有人测过。

### 验证实验（按顺序）

**V1　笔记本能不能用（2–3 小时，不训练）**
- 做法：下载基座；用 data/ 里现成的模板记忆对话取 40 条事实，分 4 个会话教，再开新会话各问一次，另加 10 道“改口”题。
- 对照：无记忆；把全部历史原文塞进上下文（上界）；笔记本检索。
- 指标：答对率（字符串匹配 + 人工看 20 条）；生成速度；显存。
- 门槛：笔记本 ≥ 80%，且不低于上界 10 个百分点；改口题 ≥ 70%。
- 不过怎么办：抽取错多 → 改成原句入库；检索错多 → 加关键词检索或把最近 50 条全放进提示；速度或显存不够 → 换 0.6B。

**V2　一晚睡眠能不能入脑（3–4 小时）**
- 做法：30 条虚构事实（保证基座不知道），按睡眠五步训一次。
- 对照：只训原句（无造题）；造题无回放；造题 + 回放 + KL（完整）。
- 指标：闭卷答对率；200 道通用题的变化；睡眠用时。
- 门槛：完整组闭卷 ≥ 50%，通用题下降 ≤ 2 个百分点，用时 ≤ 30 分钟。
- 不过怎么办：闭卷低 → 加秩、加问法数、加步数，各试一次；仍低则把定位改成“笔记本为主、参数只学风格与能力”（系统仍满足全部需求，只是知识主要在外置记忆）。通用题掉得多 → 加大 λ 或降学习率。

**V3　连续 7 晚**：每晚新增 20 条事实与一小时真实对话。指标：第 1 晚学的事实到第 7 晚的闭卷保持率、通用题漂移、被回滚的次数。门槛：保持率 ≥ 第 1 晚的 80%，回滚 ≤ 2 次。不过 → 历史事实题的回放比例加倍；每周从档案里最好的祖先重新合训一次。

**V4　能力与适应**：选一个用户常做的任务连用两周，按上表测；门槛：留出题上超过冻结基座，用户盲选偏好率 > 60%。不过 → 加该领域公开语料进夜间训练。

### 最可能失败的地方

1. **闭卷入脑率低**。公开结果里 7B 模型靠自造数据也只把无上下文问答做到一半左右；1.7B + 低秩可能更低，且“教的是陈述句、问的是问句”这一步泛化最弱。对策已写在 V2；最坏情况是知识长期住在笔记本里，这违背用户“知识进参数”的愿望，但不影响可用性。
2. **抽取出错污染笔记本**：小模型可能把玩笑、假设句记成事实。对策：保留来源句与时间，用户可用“忘掉 X”删除；冲突时以新的为准并保留旧值。
3. **多晚累积漂移**：每晚都过验收，但几十晚后整体悄悄变差（验收只看当晚）。对策：验收里固定一组永不更换的通用题，对比的是原始基座而不是昨晚；档案按“后续几晚是否持续过关”选祖先。
4. **工具链**：4-bit 量化库在 Windows 上的兼容性未验证；不行就用 0.6B 的 bf16 全精度（不需量化）。
5. **1.7B 的智力上限**：复杂推理仍会错。可开思考模式换时间，但这是基座的天花板，本方案不解决。
