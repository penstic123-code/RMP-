## 17　十套从零设计的方案：总览（2026-11-20，均未实施）

来源：三个独立代理（Fable）并行从零设计，只读文献目录（[literature/](../../literature/README.md) 的 README、7 个主题、5 张实现卡）与全部实验记录，没有读任何设计文档与排期。需求按用户 2026-11-20 的要求：训练不能太慢、有智力、会说话（英文）、能持续改进自己（知识、能力、适应用户三种都要）、有记忆；希望参数在使用中改变；可以用现成预训练模型。成功概率是各代理的主观估计；所有吞吐与显存都是估算，没有实测。

### 17.2　十套方案的共同点

1. **十套里八套借现成模型保证“会说话、有常识”**。只有 P3、N3 从零训，它们的“有智力”都被代理自己评为最弱。创新几乎全部集中在主干之外：记忆怎么写、参数何时怎样改、怎样防遗忘。
2. **都要先赢一个朴素基线**：把原文检索进上下文。P1、X1、X2、X3、N1 都把它列为第一个实验的对照，而且都承认在纯事实回忆上可能输给它。新机制的价值要在“换了说法还记得”“能力变强”“不占上下文”上体现。
3. **防遗忘的共识**：改动局部化（低秩插件、克隆、柱、海马表、用户专属矩阵）、复习旧数据、锚定改动前的模型、过考才提交、可回滚。与本项目 E25、E29、E31 的结论一致。
4. **“使用中改参数”的分歧最大**：P2、N2、N4、X1、X2 当场改；P1、N1 只在夜里改；X3 在空闲时改。当场改的几套都把“学习率在学得动与不带偏之间的余地很窄”列为主要风险。

### 17.3　可以怎样组合

- **X3 是框架，其他几套可当它的“编译后端”**：X3 先查表、再把热点编译进参数。编译这一步可以用 P1 的夜间低秩插件，也可以换成 X1 的克隆、X2 的卡尔曼写入或 N4 的柱。代理 X 自己也指出了这一点。
- **共用的评测**：十套都需要同一套考卷——闭卷事实（含换说法）、跨会话、常聊领域的成长曲线、适应用户、旧能力不退步。先把评测和模拟用户脚本做好，所有方案都能直接比。
- **主干可共用**：八套用现成模型，可统一先选一个基座（Qwen3-0.6B 或 Qwen2.5-0.5B 级，1.7B 视显存而定），在同一基座上换记忆机制比较。

### 17.4　协调者建议的顺序（供用户决定，未排期）

1. 先跑 X3 的“上限测量”（约半小时）：小模型带资料、多想几遍，比直接回答强多少。这个数决定“能力越用越强”有多少东西可学，对所有方案都有用。
2. 搭共用的生活层与考卷，在同一基座上跑朴素基线（检索进上下文）与 P1（夜间低秩插件）。
3. 在同一框架里依次换上 X2、X1、N4、N2 等“当场改参数”的写入方式，各自和 P1、朴素基线比。
4. 从零训练这条线（P3、N3）作为“自己的模型”的长期研究，与前面并行、夜里跑。

各方案的验证实验、依据与风险见各自文件。
