## 17-X3　分层即时编译（JIT）

借鉴领域：编译器与语言运行时（解释器、热点剖析、分层即时编译、守卫与去优化、回归测试）。标注：[V] = 本次打开原文核实；[未核实] = 凭记忆或二手来源；“估算”= 未实测。

### 1. 一段话总述

像 Java 或 JavaScript 的运行时那样，让模型有两种执行方式。**解释执行**（慢而稳）：新知识先以文字形式记在“符号表”里，回答时检索进上下文；需要时多想几遍、查本地资料、投票。它立刻可用、不会忘。**编译执行**（快）：同样的行为被“编译”进参数，不再占上下文。一个剖析器统计哪些事实、话题、任务被反复用到（“热点”）；只有热点才值得编译。编译的方法是让“不带上下文的模型”去模仿“带上下文、多想几遍的自己”。每个编译单元都带一组自动生成的测试题和一个守卫：守卫不成立或抽查不一致时，退回解释执行并作废重编。所以系统任何时候都不比解释执行差，编译只决定它变得多快、多强。主干用现成的小型对话模型（Qwen2.5-0.5B-Instruct，备选 SmolLM2-360M-Instruct），保证会说话。

### 2. 借鉴的原理与对应关系

| 运行时系统 | 本方案 | 类比还是真机制 |
|---|---|---|
| 解释器 | 检索符号表 + 用户档案卡进上下文；可选 k 次采样投票、查本地语料 | 真机制 |
| 符号表 | SQLite 里的事实条目（带版本号、来源句、时间） | 真机制 |
| 剖析器与热点 | 每条事实 / 每个话题簇的命中计数与最近使用时间 | 真机制 |
| 第 1 级编译（快、粗） | 每个话题一个小的“前缀键值块”（Cartridges 式），空闲几分钟训成 | 真机制 |
| 第 2 级优化编译（慢、精） | 夜间把最热的单元合成主干上的一个 LoRA 并入权重 | 真机制 |
| 常量折叠、内联 | 热事实从“每次查表”变成“权重里直接知道” | 类比（实现就是上下文蒸馏） |
| 守卫 | 话题分类器（中间层隐状态的线性探针）+ 事实版本号 | 真机制 |
| 去优化 | 守卫失败、版本过期或抽查不一致 → 本次回到解释执行，单元标记待重编 | 真机制 |
| 死代码消除 | 长期不命中的单元被卸载，文字仍留在符号表 | 真机制 |
| 持续集成 | 每个单元自带测试题；每晚全量跑，未过不提交 | 真机制 |
| 自举（用编译器编译编译器） | 编译后的模型成为下一轮解释器的底座 | 类比；能否逐轮变强是假设 H2b |

关键的真机制是**编译目标**：不是对原始对话做下一词预测，而是让学生（无上下文 + 编译单元）在自生成的问题上逼近老师（同一模型 + 上下文）的输出分布，即上下文蒸馏。

### 3. 结构与规模

- 主干：Qwen2.5-0.5B-Instruct（约 4.9 亿参数，24 层、隐层 896；Apache-2.0 [未核实许可细节]），半精度约 1 GB 显存。
- 符号表与日志：SQLite；检索用主干自己的句向量（中间层平均池化），不够好再加一个 2,200 万参数的小嵌入模型。
- 第 1 级单元：每层 16–32 个虚拟位置的键值前缀，约 20 万参数 / 个（估算），可同时加载多个（Cartridges 报告可组合 [V 摘要]）。
- 第 2 级：全层秩 16 的 LoRA，约 900 万参数（估算），每晚训练后并入；并入前的权重保留为版本（提交 / 回滚）。
- 守卫：896→话题数的线性探针，可忽略。
- 显存：解释执行（上下文 2k 词元、k=5 批量采样）约 2 GB；第 1 级编译（批 4×512）约 3 GB（估算）。全程可控制在 3–4 GB 内。
- 吞吐：快速路径 40–80 词元/秒；解释路径因上下文更长、k 次采样并成一批，延迟约为 1.5–2 倍（均为估算）。
- 离线准备：无主干训练。建本地语料索引（Cosmopedia / FineWeb-Edu 的一个子集）约 1 小时；守卫探针几分钟。

### 4. 学习方式

- **离线**：不训练主干。可选：若闲聊质量不足，用 SmolTalk 做一次几小时的 LoRA 微调并入。
- **使用时**：
  - 第 0 级立即生效：用户教的事实、纠正、偏好由主干抽成条目写入符号表（原句同时保留）；同一键的新值使旧版本作废，所有依赖旧版本的编译单元立即去优化。
  - 每轮结束后，为新条目自动生成 4–6 条测试题（改写问法、间接问法、换名反例），并用解释执行的答案作标准答案。
  - **参数何时改**：在用户阅读、打字的空隙里后台跑第 1 级编译，每步约 0.2 秒（估算），可随时让出显卡。所以参数确实在一次会话内改变，但不是逐词元同步改。理由：同步改参数要么慢、要么冒遗忘的险；而符号表已经让新知识立刻可用，参数更新不必抢这几秒。
- **空闲 / 夜间**（第 2 级）：
  1. 取剖析器排名前列的单元与话题；
  2. 老师 = 解释执行（检索 + 投票 + 查资料），在这些话题的自生成问题与真实历史问题上产出答案分布；
  3. 学生 = 无上下文的主干 + LoRA，最小化与老师的 KL；同时混入普通对话上对昨晚自己的 KL 作锚（本项目里锚定是唯一稳定提交的睡眠方式，E31、E36）；
  4. 持续集成：全部单元测试 + 普通对话回归。全过才并入并提交；否则回滚，只保留第 1 级。
- **防遗忘**：文字永远是真相来源，参数是可丢弃的缓存；回归测试挡在提交前；锚定 KL。最坏情况是“编译失败、退回查表”，不是“忘了”。

### 5. 三种自我改进与记忆：怎么实现、怎么测

| 需求 | 实现 | 测法 |
|---|---|---|
| 知识 | 符号表（立即）→ 第 1 级 → 第 2 级 | 开卷（允许查表）与闭卷（关掉符号表）正确率分开报告；闭卷正确率随编译上升 |
| 能力 | 热点话题上蒸馏“多想几遍 + 查资料”的自己 | 热点领域留出题的快速路径正确率逐夜曲线；冷门领域作对照 |
| 适应用户 | 档案卡（模型维护的一页文字：称呼、偏好、常用说法）先在上下文里起作用，再编译成风格 LoRA | 拿掉档案卡后的偏好遵守率 |
| 会话内记忆 | 上下文窗口 | 多轮指代题 |
| 跨会话记忆 | 符号表 + 已编译单元 | 重启后提问；改口后旧值复现率；删除条目后闭卷也答不出（需重编该单元，V2 检查） |

### 6. 核心假设，以及为什么可能赢过普通 Transformer

- **H1（可编译）**：带自生成问题的上下文蒸馏，能把热点单元 85% 以上的开卷表现搬进参数，并明显好于对原文做下一词预测。
- **H2（放大可蒸馏）**：解释执行比快速路径强（差距 ≥8 个百分点），且蒸馏能把差距收回一半以上。H2b：重复几轮后解释执行本身也变强（把握小）。
- **H3（按热点分配）**：同等夜间算力下，按使用频率选编译对象，比均匀巩固全部日志的“按使用加权正确率”更高。
- 为什么可能赢：普通 Transformer 只有两个选项——全放上下文（不会变强、窗口有限），或直接微调日志（本项目见过它忘得厉害，E25、E29；做梦式巩固还会削弱新内容，E36、E37）。本方案把“正确性”与“巩固质量”拆开：正确性由文字和守卫负责，巩固只是优化，可以失败、可以重来。E36 的教训（老师不认识新词时，蒸馏等于教学生忘掉新词）在这里被正面处理：老师永远是“带上下文的自己”，它认识新内容。

### 7. 主观成功概率

- 满足全部用户需求：**65%**（三套里最高）。因为第 0 级就已满足“会说话、有记忆、记住用户教的东西”，剩下的是把它变成参数与能力。
- H1：60%（上下文蒸馏与 Cartridges 有先例，但在 0.5B 上未见报告）；H2：35%（小模型多想几遍的增益可能很小）；H2b：15%；H3：50%。
- 风险在于：若 H1、H2 都不成立，系统仍能用，但只是“检索 + 档案卡”，创新为零。

### 8. 依据

- Learning by Distilling Context（Snell、Klein、Zhong，2022，arXiv 2209.15189）：模型带着指令与草稿作答，再微调自己在不带它们时给出同样答案；能内化指令、逐步推理与样例，内化样例在 SPIDER 上比直接梯度学习高 9% [V 摘要]。
- Cartridges（Eyuboglu 等，2025，arXiv 2506.06266）：离线训练的小键值缓存替代长上下文；训练配方是生成关于语料的合成对话 + 上下文蒸馏；作者称对语料直接做下一词预测不敌上下文内学习；内存省 38.6 倍、吞吐高 26.4 倍，可组合 [V 摘要]。
- Expert Iteration（Anthony、Tian、Barber，2017，arXiv 1705.08439）：搜索产出更好的方案，网络学着泛化它，再反过来指导搜索 [V 摘要]。本方案把“搜索”换成“检索 + 多次采样投票”。
- Self-Consistency（Wang 等，2022）：多次采样投票提高推理题正确率 [未核实；且在 0.5B 模型上的增益未知]。
- 分层编译、守卫与去优化是 HotSpot、V8 等运行时的通用做法 [常识，未查原文]。
- WISE（NeurIPS 2024，arXiv 2405.14768）：纯检索式记忆难以让模型泛化所学，直接改主参数又伤局部性 [V 摘要]——支持“文字与参数两级并存”。
- 本地文献：cards/sleep-2.md 第 12 卡（SEAL：让模型自己写训练材料；连续编辑会遗忘）、第 10 卡（LMs Need Sleep：on-policy 蒸馏把短期记忆搬进参数）、第 9 卡（自生成回放 + KL）、第 13 卡（检查点档案 → 版本提交 / 回滚）、第 14 卡（换名反例 → 单元测试）；cards/sleep.md 第 7 卡（间隔重复 → 剖析器的时间维度）；topics/chat-data.md；topics/cognition-selfimprove.md（哥德尔机：实测过了才改写自己）。
- 本项目实验：E25、E29（在线微调遗忘）；E31、E33（锚定睡眠可提交）；E36、E37（老师不认识新内容时蒸馏有害；验收题必须与报告题分开）；E18、E23（从零训的小模型学不会复制名字 → 用预训练主干 + 文字符号表）。

### 9. 验证实验（按顺序）

1. **V1 编译是否成立（约 3 小时）**。数据：100 条个人事实（data/ 的模板记忆对话）+ 3 个话题各 30 段说明文。对照组：A 解释执行（开卷，上界）；B 上下文蒸馏 + 自生成问题（本方案）；C 对原文做下一词预测（同步数）；D 对聊天日志直接 LoRA 微调。指标：闭卷改写 / 间接问法正确率；普通对话困惑度漂移；单元测试通过率。门槛：B ≥ A 的 85%，B 比 C 高 15 个百分点以上，漂移 ≤2%。不过怎么办：B 与 C 持平 → 去掉自生成问题，简化；B、C 都低于 60% → 加大单元容量再试一次，仍不行则事实永久留在第 0 级，只编译风格与能力。
2. **V2 守卫、去优化与删除**：20 条改口、20 条删除、200 个话题外问题。门槛：过期值复现 <2%；守卫漏判 <5%；误去优化 <15%（只损失速度）。
3. **V3 有没有东西可蒸馏**：在一个热点领域的留出题上，测 快速路径 / +检索 / +检索+投票 三档正确率。门槛：最强档比快速路径高 8 个百分点。不过 → H2 判死，能力改进改为“检索语料上的领域微调”，方案其余部分照常。过 → 蒸馏一晚，再测快速路径，门槛为收回差距的一半。
4. **V4 三十夜持续集成**：模拟 30 天使用。门槛：单元测试通过率不降，普通对话漂移累计 ≤3%，没有一晚需要人工干预。
5. **V5 按热点分配**：H3 的对照（均匀巩固 vs 按热点），同算力。

### 10. 最可能失败的地方，以及失败能学到什么

- **放大太弱**：0.5B 模型多采样几次、查资料后可能并不明显更对，则“能力”一项只剩领域微调。V3 第一步半小时就能量出这个差距，是整个“自我提高智力”路线的上限测量，对任何方案都有用。
- **抽条目出错**：让小模型把用户的话抽成符号表条目，可能抽错或漏抽。对策是原句同时保留并可检索；测试题由原句生成。
- **守卫不准**：话题边界模糊时，编译单元在不该用的地方生效。代价可控（抽查 + 去优化），但会拖慢。
- **看起来不够“神经”**：知识先在文字里，这是有意的取舍——它让系统从第一天就可用，并给参数学习提供了永远正确的老师。若用户更看重“纯参数内学习”，本方案的第 1、2 级编译器可以换成 17-X1 或 17-X2 的写入方式，三者不冲突。
