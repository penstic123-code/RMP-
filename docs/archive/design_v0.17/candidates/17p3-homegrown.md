## 17-P3　自家苗（从零训 7,000 万参数的普通 Transformer，现成模型只当出题老师，夜夜续训）

### 一段话总述

模型完全自己训：一个约 7,000 万参数、子词级的标准 Transformer，先用两个通宵在公开语料上学语言和常识，再用对话数据学聊天，训练数据里从一开始就带“记忆栏”格式，让它学会读自己的笔记。现成的开源大模型（Qwen3-1.7B）**不上线、不进权重**，只在本机当“出题老师”，离线生成简单的常识、推理和记忆对话。上线后，它每晚把当天的对话混进下一段预训练语料里接着训——因为模型小、离饱和很远、又握有全部原始训练数据，“继续训练”本身就是它持续变聪明的方式。这一套自主程度最高，也是三套里智力上限最低、成功概率最低的。

### 结构与规模

| 项 | 取值 | 说明 |
|---|---|---|
| 架构 | 仅解码器 Transformer，12 层，宽 640，10 头，MLP 4 倍 | 旋转位置编码、RMSNorm、q/k 归一化；全是成熟件 |
| 分词 | 自训 BPE，词表 16,384 | 小词表省嵌入参数；输入输出嵌入共享 |
| 参数 | 约 7,000 万（主体约 5,900 万 + 嵌入约 1,050 万，估算） | 可调到 5,000 万（10 层）或 1 亿（14 层、宽 704） |
| 上下文 | 1,024 词元（训练）；推理可滑窗 | |
| 优化器 | 矩阵用 Muon，其余 AdamW；bf16 | nanochat 同款配方 |
| 显存 | 批 32 × 1024 约 5–6 GB（估算）；批 16 约 3 GB | 渲染程序开着时用批 16（E39） |
| 吞吐 | 目标 ≥ 2.5 万词元/秒（估算，V1 实测） | 一夜 10 小时 ≈ 9 亿词元 |

不用自研模块的理由：文献结论是小规模下各架构差距多在噪声内，形状与调参影响更大（topics/architectures.md 末节；E30、E32 也显示形状比机制重要）；本项目的自研结构吞吐曾远低于对照（E14），长训练中途数值溢出过（E41），新增机制多次同参数变差（E34、E35、E38、E40）。从零训的预算很紧，只能用最快、最不会出意外的结构。不依赖 Triton：注意力用 PyTorch 自带的高效实现；`torch.compile` 能用则用，不能用约慢三成。

### 学习方式

**离线（约 3 个通宵 + 出题）**
1. **出题（可与训练错开，约 1 晚）**：Qwen3-1.7B 在本机按模板批量生成约 3,000 万词元：受限词汇的常识问答、两三步的简单推理（带一步步写出的过程）、带记忆栏的多会话对话。这是“老师写教材”，不是蒸馏权重。
2. **预训练（2 晚，约 18 亿词元）**：FineWeb-Edu 子集（主体）+ Cosmopedia（教科书式常识）+ TinyStories（简单叙事）+ 老师的教材。普通下一词元预测。
3. **对话训练（1 晚，约 5 亿词元）**：SmolTalk（删减版）、TinyChat、TinyDialogues、SODA、本地模板记忆对话、老师生成的记忆对话，仍混入 20% 预训练语料防忘。轮次边界用专门的标记，采样时遇到用户标记就停（TinyChat 的教训）。
4. **记忆栏格式**（贯穿 2、3 步）：每段对话前有一段 `<mem>…</mem>`，里面是若干条事实，其中只有一部分与后面的提问相关；提问放在隔了很多无关轮次之后，**回答部分的损失加权**（延迟提问监督）。还要有“记忆栏里没有 → 回答不知道”的样本。这样模型学到的是“先看笔记再回答”这个通用技能。

**使用时（每轮改一小部分参数）**
- 回复后做 1–2 步低秩更新（做法同 17-P2 的在线步：一半新内容、一半回放，只动 LoRA），因为模型只有 7,000 万参数，一步约 0.1 秒。
- 新事实同时由规则 + 模型自己抽成一行，写进笔记文件，下一轮起出现在记忆栏里。小模型抽取能力差，所以规则优先：含 “my / I am / I like / remember” 的句子原句入栏。

**睡眠时（每晚，整模型续训）**——这是本方案的核心差别：
- 训练集 = 新一段预训练语料（每晚 5–9 亿词元，硬盘上取之不尽）+ 当天对话与笔记改写成的记忆对话（重复 20–50 遍，占比约 1%）+ 历史用户数据的回放。
- **全部参数都训**，不止 LoRA；白天的 LoRA 在睡前丢弃（它只是当天的临时记忆，内容已在训练集里）。
- 防遗忘主要靠“真回放”：旧知识的原始数据就在硬盘上，始终占训练集的 99%，所以不需要自生成回放或锚。
- 验收：通用验证集损失不升（实际应下降，因为在继续学新语料）；用户事实闭卷答对率升；固定常识题不降。不过则回到昨晚的检查点（每晚存一份，约 280 MB）。
- 用户常聊的领域：从 FineWeb-Edu 里按关键词多抽该领域的文档进当晚语料——“能力”的增长有明确的数据来源。

**为什么可以放心整模型续训**：文献指出遗忘严重与否取决于模型是否饱和；7,000 万参数只见过二十几亿词元，远低于饱和水平（SmolLM2 的同级模型见过上万亿），余量很大。可塑性丧失按拟合也要到远超我们用量的数据量才出现。

### 三种自我改进与记忆：怎么实现、怎么测

| 需求 | 实现 | 测法 |
|---|---|---|
| 会话内记忆 | 1,024 词元窗口 + 记忆栏 | 同会话隔 10 轮提问 |
| 跨会话记忆 | 笔记文件 → 记忆栏；每晚进参数 | 新会话提问，带栏 / 闭卷各报一个数；隔 1 / 7 天 |
| 知识 | 笔记（即时）+ 夜间续训（入参数） | 闭卷答对率；反事实换名对照 |
| 能力 | 夜间续训本身 + 领域语料加抽 | 通用验证损失与固定常识 / 推理题的逐晚曲线；领域留出损失 |
| 适应用户 | 白天 LoRA（即时）+ 对话进夜间训练 | 对用户下一句话的困惑度逐周下降；偏好遵守率 |

“逐晚曲线”是这一套独有的看点：用户能直接看到模型每晚的验证损失在降、常识题分数在涨。

### 成功概率与理由

主观成功概率 **约 20%**（六条全部达到用户满意的水平）。分项：会说简单英文对话约 85%；带记忆栏的跨会话记忆约 70%；夜间续训能吸收用户事实且通用能力不降约 60%；**“有智力”达到用户预期约 25%**——这一项决定总数。

支持它能成的部分：7,000 万参数、20 亿词元量级的小模型能流利地写简单英文、做简单问答，已有公开先例（TinyStories、TinyChat 用更小的模型做到了简单闲聊）；训练流程全是成熟配方；自己握有全部训练数据使持续学习变成最简单的一种——接着训。

压低概率的部分：公开的同级小模型（SmolLM2 的 1.35 亿、3.6 亿参数档）是用我们上千倍的词元训出来的，它们的常识与推理尚且有限；本方案一个月的夜训总量也只有它们的百分之一左右。文献也指出面向小模型删减过的指令数据对很小的模型仍偏难（topics/chat-data.md）。所以诚实的预期是：**像一个词汇有限、会聊天、记得住你说过的话、每周都进步一点的小孩**，而不是一个助手。如果用户对“智力”的要求高于此，应选 P1 或 P2。

### 依据

- nanochat（Karpathy，开源项目，本次核实 README）：单机全流程训练对话模型，AdamW + Muon，SmolTalk 微调；其目标规模在 8 张 H100 上约 2 小时，单卡约慢 8 倍——说明我们只能取其小号配置。
- SmolLM2（2025，arXiv 2502.02737，本次核实摘要与 360M 模型卡）：数据为中心的小模型训练，FineWeb-Edu 等 + SmolTalk；训练量达数万亿词元。
- Forgetting in LMs（2026，arXiv 2605.26097，本次核实摘要）：饱和模型才救不了；回放使高学习率微调不遗忘。
- Delayed Supervision（2026；cards/memory-workspace.md 第 7 条）：隔很久再问并只对答案加权。
- TinyChat15M、TinyDialogues（cards/topdown-data.md 第 6 条）：受限词汇对话数据、轮次标记、对话内顺序不可打乱。
- Dialogue Is Not Enough（2025；topics/chat-data.md）：只用对话预训练通用能力差——所以先通用预训练再对话。
- Muon（cards/fast-memory.md 第 2 条）。可塑性丧失的规模律（cards/sleep-2.md 第 15 条）。
- 架构不是瓶颈：topics/architectures.md“极小规模的头对头对比”一节。
- 本项目实验：E14、E41（速度与稳定性）；E30、E32（形状）；E34、E35、E38、E40（新增机制同参数变差）；E18、E23（太小的模型不会利用前文）；E25、E29、E31（在线与睡眠）；E39（显存）。

### 验证实验（按顺序）

**V1　速度与小样（3–4 小时）**
- 做法：先用 7,000 万配置空跑 10 分钟测吞吐与显存；再用 3,000 万参数的缩小版在 TinyStories + TinyChat 上训约 1.5 亿词元，生成 20 段对话人工看。
- 对照：同数据同步数的 GRU 与本项目现有最好配置各一个（只比每小时能降多少损失）；`torch.compile` 开 / 关。
- 指标：词元/秒、显存、验证损失、对话是否守轮次。
- 门槛：7,000 万配置 ≥ 2.5 万词元/秒且显存 ≤ 6 GB；小样对话语法基本正确、不替用户说话。
- 不过怎么办：速度不够 → 降到 5,000 万或上下文 512；仍低于 1.5 万 → 本方案的两晚预算不成立，放弃 P3。

**V2　记忆栏学得会吗（一晚）**：缩小版加记忆栏数据训练。对照：无记忆栏；有记忆栏无损失加权；有加权。指标：栏内事实的答对率、栏内无关事实的误用率、“不知道”的正确率。门槛：答对 ≥ 80%。不过 → 加大记忆对话占比；缩短事实与提问的间隔后再逐步拉长。

**V3　完整三晚训练**：门槛：验证损失达到 V1 外推值；20 道人工常识题答对过半；能进行 5 轮不跑题的闲聊。不过 → 再训两晚（损失仍在降就继续）；若已不降则加到 1 亿参数重来，代价是再 4–5 晚。

**V4　夜间续训 5 晚**：每天教 20 条事实。门槛：闭卷答对 ≥ 50%，通用验证损失逐晚不升，5 晚内回滚 ≤ 1 次。不过 → 用户数据占比加倍；或改为“LoRA 入脑 + 整模型只训公开语料”两路分开。

### 最可能失败的地方

1. **智力不够**：这是结构性的，不是调参能解决的。三晚之后它会聊天但常识浅、推理基本不会。每晚续训能涨，但按公开模型的训练量推算，要追上最小的现成模型需要以年计的夜晚。
2. **老师教材的偏差**：1.7B 生成的常识与推理题本身有错，学生会照学。对策：教材只占小比例，主体仍是人写的公开语料。
3. **用户数据占比难调**：占 1% 可能学不进，占 10% 可能把模型带成只会聊用户那几件事。V4 专门扫这个比例。
4. **训练中断与数值问题**：通宵训练中途出错的事本项目遇到过（E41）。对策：每 30 分钟存检查点，损失异常自动回退并降学习率。
5. **1,024 词元窗口**：会话一长，早先内容滑出窗口，只能靠笔记抽取，而小模型的抽取不可靠——规则抽取兜底，但覆盖面有限。
