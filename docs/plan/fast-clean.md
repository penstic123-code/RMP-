# 提速与去重（2026-11-20 用户定的优先级）

返回 [排期](README.md)。用户最想要两件事：**1. 训练提速；2. 部件配合好，去掉打架、重复的部件。** 本页取代 [v2.md](v2.md) 任务队列第 8、11 条和 README 旧“下一步”第 0–2 项；v2.md 其余条目（v2.1、主干对比、动态分块）排在本页之后。

## 为什么两件事要一起做

- 现在最大的开销是工作空间带来的块串行：`forward` 把每个 1024 字节的窗口切成 16 段，每段 64 字节，逐段串行跑完全部层（dspn_text.py `DSPNLayered.forward`）。小运算本来就没融合（E41：GPU 满负荷，批再大也不快），这样又多了 16 倍。
- 第 20 章的“中枢块末广播给所有层”还是同一个环路：下层 → 中枢 → 下一块的下层，串行照旧，所以这一条必须重新设计（见 A2）。
- 重复的部件同时就是慢的部件。死开关（词级、td、卷积、输出门、RIMs 冻结、网格邻接）让每个前向多出分支和小运算，也挡住了 torch.compile 和 fla 内核的接入。

## 阶段 A：提速（目标是 L 档字节/秒到 E41 的 3 倍，约 20 万）

每一项都用同一个基准：L 档 overnight 配置（去掉工作空间那一项除外）、批 16 × 1024、1500 步，看 JSON 里的 `train_bytes_per_sec` 和 `peak_gpu_mb`。每项只跑一次，不重复测。数值等价的改动只要求测试通过（最大差 < 1e-3），不重训；改了结构的改动还要求验证 bpc 不比改前差 0.013 以上。

| 步 | 做什么 | 预期 | 过关 |
|---|---|---|---|
| A0 | 打 git 标签 v0.16；用现行代码跑基准，作为起点 | — | 登记 E 编号 |
| A1 | 删死代码（上表“删”的各项，以及 B1 的全部）。关掉的选项走同一路径，输出应与 v0.16 完全一致 | 少量提速，但这是 A3、A4 的前提 | 现有测试改写后全过；同一检查点的 logits 与 v0.16 一致 |
| A2 | 去掉块串行：删工作空间。广播改为**窗口级**：下层在整个窗口里读到的是中枢在上一窗口末的读出（RMS 归一化，零初始的门），整窗一次并行算完。跨批次延续状态训练时这一项是免费的；聊天时每满 1024 字节更新一次，与训练一致 | 最大一项，约 16 倍串行变 1 次 | 字节/秒；流式 bpc 与“无广播”比，不好于它超过 0.013 就把广播也删掉 |
| A3 | 全部换成 fla 融合内核：快记忆与中枢用 `chunk_gated_delta_rule`，慢通道 c 的对角递推用 fla 的 HGRN 类内核，替代 Python 的分块扫描。E53 那次 500 步试跑含编译开销，这次用 1500 步重测 | 前向 + 反向数倍 | 与参考实现的最大差 < 1e-3；字节/秒 |
| A4 | bf16 自动混合精度（门、状态、对数累乘保持 fp32）。fla 内核在对数域处理门，不再有块长 16 时 e^73 的溢出问题（E41） | 约 1.5–2 倍 | 1500 步验证 bpc 不比 fp32 差 0.013 以上 |
| A5 | torch.compile 融合门、投影这些逐元素小运算，与现有的整步 CUDA Graph 配合；不兼容就只编译 Layer 的逐元素部分 | 小运算合并 | 字节/秒 |
| A6 | 按层做激活检查点，批加到 32 或更大 | 显存换吞吐 | 字节/秒；E41 的批 24 曾溢出显存 |

A 做完后按结果定放大目标（同 v2.md 放大路线第 2 步）：≥ 3 倍就做 3000 万参数，否则 1000–1500 万。
